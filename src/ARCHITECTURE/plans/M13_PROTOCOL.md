## 目標與評估用途

將「這次到底測了什麼、哪些資料用來選參、結果能否重現」變成可查證產物。開發期仍為 2021–2023、驗證期 2024、2025 年後維持歷史探索性評估。先凍結本輪候選及判定規則，再執行候選搜尋；新協議不能將已接觸歷史資料變成真正的前向預註冊。

未來未見資料的前向觀察須另外指定開始時間、資料接觸紀錄與固定策略；策略變動另開實驗，不在同一績效線替換歷史。研究驗收不設「必須賺錢」條件；結論可以是策略無優勢或樣本不足。

## 先定義的公開契約

建議拆分 `study_protocol.py,experiment_registry.py,odd_lot_benchmarks.py,odd_lot_diagnostics.py`，各檔不超過 300 行。名稱為規劃，尚無這些公開介面。

| 型別／介面 | 必要內容 |
| --- | --- |
| `StudyProtocol` | schema、期間用途、標的／基準、暖機、候選集合與搜尋上限、選擇規則、成本／風險／交割假設、種子、資料與日曆指紋、資料接觸情況 |
| `ExperimentRecord` | protocol ID、parent ID、候選 ID、狀態、資料 ID、程式 revision／未提交差異 hash、環境 ID、結果 fingerprint、失敗原因 |
| `BenchmarkSpec` | 投資標的、初始資金、開始／成交規則、委託補單政策、現金股利／再投資、成本與交割模型；明確是否可交易 |
| `EpisodeRiskAudit` | episode ID、建倉時風險預算、首次止損訊號、退出嘗試、股份出清時間、未平倉狀態及淨實現損益 |
| `freeze_protocol()/register_experiment()` | canonical identity；既有協議不可覆寫；成功與失敗候選都保留紀錄 |

同一協議＋資料＋程式／環境＋候選形成確定性實驗身分。報告目錄 UUID／產製時間可不同，數值業務結果的 fingerprint 應一致。改參、換資料或程式差異必須產生新身分。

## 基準與數值口徑

1. 保留 ensemble、momentum、同股票池等權，以及 0050 無交易成本總報酬參考；各自標註模型種類。
2. 新增可交易的單一 0050 買入持有基準，明確填 ETF 規則，採相同初始資金、價格／滑價、費用、每筆 999 股、成交比例與交割語義。
3. 初版可交易基準沿用期初一次委託、剩餘量當日到期的被動政策，不套策略止損；股息保留現金、不自動再投資。實際投資比例與剩餘現金一起報告，不能默認已全額投資。
4. 現有 study 至少兩檔交易股票的守門維持；單一 ETF 基準走明確獨立介面，共用撮合與帳務，不以放寬研究主體限制來接入。
5. 不把無成本參考與可交易績效混成同口徑排名。各結果使用相同期間及暖機規則，不能因績效挑選起迄。

淨損益依實際成交、費用、股利、拆股及結算重建；滑價已在成交價內，不再從損益重複扣除。Profit factor、勝率、payoff、期望值及最大回撤沿用明確定義；分母不存在則回傳可解釋的資料不足，不造零值或無限大當有效指標。

## 執行工作包

| ID | 動作 | 交付／退出條件 |
| --- | --- | --- |
| R01 | 定義協議、資料接觸紀錄、有限候選集合與選擇／拒絕規則 | 經 schema 驗證的協議；本輪未執行候選評估前完成凍結 |
| R02 | 實作實驗登記與 lineage，接現有 freeze/run/export | 重跑身分穩定，失敗候選可追溯；改參無法覆寫先前紀錄 |
| R03 | 加入可交易 0050 基準並驗證單一資產帳務 | 手算 fixture、同成本／交割情境與部分成交檢查通過 |
| R04 | 加入資金使用率、未成交原因、止損延遲及風險預算超額診斷 | 計算來源可追溯至 orders/fills/episodes；缺來源時明列 unavailable |
| R05 | 接入已相容的成本／成交比例敏感度及研究報告 | 情境集合先凍結；報告不以評估結果回頭選最有利假設 |
| R06 | 經資料就緒檢查後執行分期研究與重現性核對 | 同輸入兩次數值一致，所有必要產物及限制進入 hash manifest |
| R07 | 產出策略繼續／退回／樣本不足的判斷紀錄 | 判斷依事前規則，保留不利結果；若改協議，建立新 parent/child 實驗 |

資金使用率先定義為每日風險持股市值／NAV，另列可支用現金及未結算占比；NAV 非正時回傳無效原因。止損延遲從首次收盤觸發至股份最後退出成交計算，未出清者列 pending，碎股權利結算另列。風險超額使用建倉時凍結預算對照實現淨虧損，不能事後反推預算。

R04 接續切分：現有 `odd_lot_diagnostics/` 三份初稿尚未完成整合與驗收；按[下一階段 D01–D04](DEVELOPMENT_NEXT.md)先補建倉預算證據，再實作 episode／pending 診斷、新協議及報告驗證。R05、R07 在該計畫另有退出條件，新增分析需保留既有 v1／v2 協議身分。

R04 工程更新：建倉 fill 已保存預算，純讀取診斷包含資金／未成交／episode 超額風險與止損退出；v3 協議明確啟用診斷，JSON／CSV／HTML 及數值指紋已接入。報告驗證從保存的帳務來源重建診斷，篡改後重算 hash 仍會因語義不符被拒。實際引擎涵蓋跳空限價失敗、部分退出、未平倉、拆股歸零但權利款待收及缺建倉預算。前段初稿描述保留作歷程；最新驗證與剩餘工作見 EXECUTION_STATUS。

R05 工程更新：`odd_lot_sensitivity/` 已提供 immutable scenario／outcome 契約、策略／ETF 相同情境矩陣、設定與完整帳戶來源保存、失敗／受阻留存及來源摘要核對。明確設定 `matched_sensitivity=True` 形成 v4 協議，沿用既有有限情境；v1–v3 保留原分析路徑。每個成功情境保存成本、成交、資金與樣本摘要，未定義指標列 null 與名稱；一個情境失敗會在完整報告保存後使 attempt failed。這是驗證期診斷，不開啟自動候選選擇；完整驗證及真實受阻資料證據見 EXECUTION_STATUS。

R07 第一單元：`odd_lot_decisions/` 已有顯式門檻政策、有限候選／情境證據、開發期排名及全量驗證門檻的純計算核心。候選缺開發證據不先選部分結果；選定後若驗證失敗不改選；同時保留已知拒絕與未知來源。此核心尚未核對真實 registry／報告來源，也未凍結到新協議或接 UI，不能用它直接執行正式候選選擇。剩餘接線與驗證見模組 README 及 EXECUTION_STATUS。

R07 接續規格見 [候選判斷與 UI](M13_DECISION_UI.md)：J00–J05 依序補政策綁定、來源 adapter、先開發選擇再驗證、聚合決策報告與 UI。新增 J-A01–A11 明列重試／來源篡改／相容性及 UI 的驗收範圍；純核心測試與完整來源核驗分開記錄。原協議 v1–v4 保持原身分，新可執行政策規劃另建 v5。

## 驗收矩陣

| 案例 ID | 情境 | 通過標準 |
| --- | --- | --- |
| R-A01 | 相同輸入與協議重跑 | 候選／實驗 ID、業務資料 fingerprint 一致；數值在以下容忍度內 |
| R-A02 | 改風險／成本／種子／資料／程式差異 | 形成新實驗身分，舊紀錄保留，不能用舊報告冒充新條件 |
| R-A03 | 完整資料對照截斷未來資料 | 同一 signal date 的既有訊號、股數、委託及成交一致；未來資料不改寫過去 |
| R-A04 | 受阻資料或不完整基準 | 在績效計算前拒絕相依期間，結果與 readiness 狀態一致 |
| R-A05 | 零成本／滿額成交的 0050 手算 fixture | 期初 100,000、價格 200 時買 500 股；收盤 210 時 NAV 105,000；成交在下一 session |
| R-A06 | 同 fixture 50% 成交與費用／交割情境 | 按事前委託政策僅買可成交部分，剩餘到期；現金與未結算占比正確，不假設滿倉 |
| R-A07 | 無勝利／無虧損／無成交／少於 30 筆 episode | 指標按定義顯示資料不足；未平倉不算已完成交易，達 30 筆也不自動標示有效 |
| R-A08 | 跳空止損、連續無法成交及最後仍未退出 | 延遲／嘗試次數與事件一致，實現超額風險正確；pending 不填成已成功退出 |
| R-A09 | 同一成交同時有滑價、佣金、稅及股利 | 淨損益與獨立手算一致，滑價及結算現金不重複扣加 |
| R-A10 | 已接觸的 2025 年後資料或未知接觸紀錄 | 報告保持探索性；checkbox 不可將未知／已接觸資料提升為未見樣本 |
| R-A11 | 候選失敗、結果不佳與成本敏感度 | 登記保留全部候選與失敗；情境未因結果被刪除，測試資料不參與選參 |
| R-A12 | 修改報告 CSV／協議／來源檔 | manifest／study 驗證失敗，HTML 與機器可讀結果能追溯同一協議與資料 |

數量、日期、狀態、指紋完全一致；現金／NAV 使用 `abs(a-b) <= 1e-6 + 1e-12 * max(abs(a),abs(b))` TWD，報酬序列用 `atol=1e-12,rtol=1e-12`。缺值須有 schema 定義及原因，NaN／Inf 不能通過有效數值欄位。
